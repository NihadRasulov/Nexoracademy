Məxfilik

Fərdi məlumatların qorunması və işlənilməsi bildirişi

1. Bildirişin məqsədi və məlumat sahibi/operator

Bu Məxfilik Bildirişi Nexora Academy rəqəmsal xidmətlərindən istifadə zamanı fərdi məlumatların hansı kateqoriyalar üzrə toplana və işlənə biləcəyini, məqsədləri, hüquqi əsasları, paylaşma hallarını, saxlanmanı, təhlükəsizliyi və istifadəçi hüquqlarını izah edir.

<

Hazırkı sayt üzrə ümumi əlaqə: info@naic.az<

2. Əsas prinsiplər

məqsədin əvvəlcədən və aydın müəyyən edilməsi;
yalnız xidmət üçün zəruri olan məlumatların toplanması;
məlumatların düzgün və aktual saxlanması;
girişin rol və zərurət əsasında məhdudlaşdırılması;
məlumatların yalnız qanuni əsas və bəyan edilmiş məqsəd daxilində istifadəsi;
saxlanma zərurəti bitdikdə silinmə və ya qanuni arxivləşdirmə;
texniki və təşkilati təhlükəsizlik tədbirlərinin tətbiqi;
istifadəçinin hüquqlarını həyata keçirə bilməsi üçün şəffaf proses.

3.1. Hesab və profil məlumatları

ad və soyad;
e-poçt ünvanı;
telefon nömrəsi (qeydiyyatda istəyə bağlı ola bilər);
dil/locale seçimi;
istifadəçi identifikatoru, rol və hesab statusu;
şifrə və şifrə dəyişmə əməliyyatına aid texniki məlumatlar. Şifrələr server tərəfində açıq mətn kimi saxlanmamalıdır.

3.2. Autentifikasiya və təhlükəsizlik məlumatları

e-poçt təsdiq kodları və giriş OTP-ləri;
access/refresh token-ləri və sessiya vəziyyəti;
giriş/çıxış və təhlükəsizlik hadisələri;
backend və infrastruktur tərəfindən yaradılan IP, vaxt möhürü, cihaz/brauzer və audit logları — yalnız faktiki olaraq toplanırsa və təhlükəsizlik/əməliyyat məqsədi üçün zəruridirsə.

3.3. Kurs qeydiyyatı məlumatları

istifadəçi ID-si və qrup ID-si;
qeydiyyat ID-si, statusu və tarixçəsi;
qeydiyyat razılığının versiyası və verilmə vaxtı;
ləğv səbəbi təqdim edildikdə həmin mətn;
ödəniş statusu və geriödəmə statusu kimi sahələr — yalnız müvafiq modul faktiki işlədikdə.

3.4. Müraciət, CV və karyera/təqaüd məlumatları

müraciət növü;
ad-soyad, e-poçt və telefon;
motivasiya məktubu;
PDF/DOC/DOCX formatında CV və CV-də istifadəçinin özü tərəfindən təqdim edilən məlumatlar;
seçim və müraciət statusu üzrə əməliyyat qeydləri, əgər backend-də yaradılırsa.

CV-də xüsusi kateqoriyalı məlumatların zəruri olmayan şəkildə təqdim edilməsi tövsiyə edilmir. Belə məlumatların emalı yalnız qanuni əsas və zərurət olduqda aparılmalıdır.

3.5. Əlaqə və lead məlumatları

ad-soyad;
e-poçt;
telefon;
müraciətin/maraq sahəsinin mətni;
mənbə və maraq etiketi kimi CRM/lead metadata-sı.

3.6. Brauzer yaddaşında saxlanan məlumatlar

Nəzərdən keçirilmiş frontend aşağıdakı funksional yaddaş mexanizmlərindən istifadə edir:

sessionStorage: access token və autentifikasiya edilmiş istifadəçi məlumatının sessiya nüsxəsi;
localStorage: refresh token;
localStorage: istifadəçiyə aid məlum qeydiyyat ID-ləri;
sessionStorage: təkrar qeydiyyat sorğusunun qarşısını almaq üçün enrollment attempt məlumatı;
localStorage: hazırkı subscribe forması üçün e-poçtun yalnız istifadəçinin cihazında saxlanılan offline nüsxəsi.

Bu yaddaşlar klassik HTTP cookie-lərindən fərqlidir, lakin yenə də cihazdakı məlumat saxlanmasıdır və məxfilik/təhlükəsizlik siyasətində açıqlanmalıdır.

4. Məlumatlardan istifadə məqsədləri

hesab yaratmaq, e-poçtu təsdiqləmək, giriş və sessiyanı idarə etmək;
profil və istifadəçi rolunu idarə etmək;
kurs qeydiyyatını yaratmaq, tapmaq, göstərmək və ləğv sorğusunu icra etmək;
kurs, təqaüd, karyera və digər müraciətləri qiymətləndirmək;
əlaqə sorğularına cavab vermək və uyğun komandaya yönləndirmək;
təhlükəsizlik, sui-istifadənin qarşısının alınması, audit və nasazlıqların araşdırılması;
qanuni öhdəlikləri və hüquqi tələbləri yerinə yetirmək;
xidmətin keyfiyyətini və etibarlılığını yaxşılaşdırmaq üçün qanuni və mümkün olduqda adsızlaşdırılmış statistik məlumatdan istifadə etmək.

5. Hüquqi əsas və razılıq

Azərbaycan Respublikasında fərdi məlumatların toplanılması və işlənilməsi, qanunla məcburi olan hallar istisna olmaqla, subyektin razılığı və ya onun yazılı şəkildə təqdim etdiyi məlumatlar əsasında aparılmalıdır. Razılıq alınarkən operatorun kimliyi, məqsəd, məlumat kateqoriyaları, emal əməliyyatları, razılığın müddəti/geri götürülməsi və saxlanmanın sonu barədə tələb olunan məlumatlar təqdim edilməlidir.

Nexora qeydiyyat və enrollment axınlarında razılığın verilməsini sübut edə biləcək versiya və vaxt qeydləri saxlamalıdır. Razılığın geri götürülməsi əvvəlki qanuni emalı avtomatik olaraq etibarsız etmir, lakin gələcək emalın hüquqi əsasını yenidən qiymətləndirməyi tələb edir.

Əgər gələcəkdə Nexora Avropa İttifaqında şəxslərə xüsusi olaraq xidmət təklif edərsə və GDPR tətbiq olunarsa, hər emal məqsədi üçün ayrıca GDPR hüquqi əsası və tələb olunan Article 13/14 məlumatları əlavə edilməlidir. Bu sənəd həmin tətbiqi avtomatik fərz etmir.

6. Məcburi və istəyə bağlı məlumatlar

Forma üzərində “required” kimi göstərilən məlumat təqdim edilmədikdə konkret əməliyyat tamamlanmaya bilər. Məsələn, hesab üçün ad-soyad, e-poçt və şifrə; əlaqə forması üçün əlaqə məlumatları; CV müraciəti üçün müraciət sahələri tələb oluna bilər. Telefon qeydiyyatda istəyə bağlı göstərildiyi hallarda onu təqdim etməmək təkbaşına hesab yaratmağa mane olmamalıdır.

7. Məlumatların paylaşılması və istifadəçi dairəsi

Fərdi məlumatlar yalnız məqsədə uyğun və “bilməli olduğu qədər” prinsipi ilə aşağıdakı kateqoriyalara verilə bilər:

Nexora-nın səlahiyyətli əməkdaşları və rol əsaslı admin/CRM/content istifadəçiləri;
hosting, verilənlər bazası, e-poçt/OTP, təhlükəsizlik, CRM və texniki xidmət provayderləri;
ödəniş modulu aktiv olduqda ödəniş provayderləri və maliyyə tərəfləri;
mühasibat, hüquq, audit və peşəkar məsləhətçilər;
qanunla səlahiyyətli dövlət orqanları və məhkəmələr, hüquqi tələb olduqda.

Provayderlərə verilən məlumat həcmi xidmət üçün zəruri minimumla məhdudlaşdırılmalı və müqavilə, məxfilik və təhlükəsizlik öhdəlikləri ilə qorunmalıdır.

8. Transsərhəd ötürülmə və hosting

<

Fərdi məlumatlar Azərbaycan Respublikasının hüdudlarından kənara ötürülürsə, belə ötürülmə yalnız tətbiq olunan hüquqi tələblərə uyğun, təhlükəsizlik və konfidensiallıq təmin edilməklə aparılmalıdır. Məlumat kateqoriyası, alıcı ölkə/təşkilat və hüquqi mexanizm daxili qeydiyyatda sənədləşdirilməlidir.

9. Saxlanma və silinmə

Qanun fərdi məlumatların məqsəd və zərurət bitdikdə silinməsini tələb edir. Nexora real sistem konfiqurasiyasına uyğun dəqiq retention schedule təsdiqləməlidir. Aşağıdakı müddətlər yüksək keyfiyyətli başlanğıc siyasət kimi tövsiyə olunur və yalnız backend faktiki olaraq bu qaydanı icra edirsə ictimai mətn kimi saxlanmalıdır:

10. Təhlükəsizlik

Nexora fərdi məlumatların təsadüfi və icazəsiz məhv edilməsi, itirilməsi, dəyişdirilməsi, açıqlanması və girişinin qarşısını almaq üçün riskə uyğun texniki və təşkilati tədbirlər tətbiq etməlidir. Bunlara rol əsaslı giriş, audit jurnalları, təhlükəsiz autentifikasiya, şifrələnmiş nəqliyyat, ehtiyat nüsxə və bərpa, zəifliklərin idarə edilməsi və processor nəzarəti daxil ola bilər.

Heç bir rəqəmsal sistem üçün “100% təhlükəsizlik” zəmanəti verilməməlidir. Təhlükəsizlik hadisəsi baş verdikdə Nexora təsirin məhdudlaşdırılması, araşdırma, bərpa və tətbiq olunan hüquqi bildiriş öhdəliklərini yerinə yetirməlidir.

11. Cookie-lər və oxşar texnologiyalar

Nəzərdən keçirilmiş frontenddə üçüncü tərəf reklam və davranış analitikası cookie-ləri aşkar edilməyib. Hazırkı kod əsasən localStorage və sessionStorage kimi funksional brauzer yaddaşından istifadə edir. Production deployment-də analitika, reklam, heatmap, üçüncü tərəf video və ya digər tracking əlavə edilərsə, bu bildiriş və tələb olunan consent/banner mexanizmi həmin texnologiya aktivləşdirilməzdən əvvəl yenilənməlidir.

12. Yetkinlik yaşına çatmayan şəxslərin məlumatları

Nexora təhsil platforması olduğuna görə yetkinlik yaşına çatmayan şəxslər xidmətlə maraqlana bilər. Qanunla tələb olunan hallarda razılıq valideyn, qəyyum və ya digər qanuni nümayəndə tərəfindən verilməlidir. Xüsusi kateqoriyalı məlumatlar yalnız ciddi zərurət və uyğun hüquqi əsas olduqda toplanmalıdır.

13. Avtomatlaşdırılmış qərarlar

Nəzərdən keçirilmiş frontenddə istifadəçi üçün hüquqi və ya oxşar əhəmiyyətli nəticə yaradan tam avtomatlaşdırılmış qərar mexanizmi müəyyən edilməyib. Belə sistem gələcəkdə tətbiq olunarsa, qərarın məntiqi, əhəmiyyəti, insan müdaxiləsi və etiraz mexanizmi barədə ayrıca məlumat verilməlidir.

14. İstifadəçi hüquqları

Tətbiq olunan Azərbaycan qanunvericiliyinə uyğun olaraq istifadəçi, şərtlərdən asılı olaraq, aşağıdakı hüquqlara malikdir:

özü barədə fərdi məlumatların mövcudluğu və operator/mülkiyyətçi barədə məlumat almaq;
toplanma, işlənmə və üçüncü şəxslərə verilmənin hüquqi əsaslandırılmasını və məqsədini bilmək;
öz məlumatlarının məzmunu ilə tanış olmaq;
məlumatların dəqiqləşdirilməsini, qanunla istisna edilmədikdə silinməsini/məhv edilməsini tələb etmək;
qanunla məcburi emal halları istisna olmaqla emala etiraz və ya qadağa tələb etmək;
məlumat mənbəyi və təhlükəsizlik/mühafizə barədə məlumat almaq;
hüquq pozuntusu olduqda səlahiyyətli orqana və ya məhkəməyə müraciət etmək və zərərin ödənilməsini tələb etmək.

Sorğunun icrası üçün şəxsiyyətin doğrulanması tələb oluna bilər. Sorğu kanalı, cavab müddəti və daxili eskalasiya prosesi Nexora-nın hüquqi prosedurunda ayrıca təsdiqlənməlidir.

15. Razılığın geri götürülməsi və hesabın bağlanması

Razılığa əsaslanan emal üçün istifadəçi razılığı geri götürmək hüququna malik ola bilər. Bunun nəticəsində həmin məlumatın tələb olunduğu xidmət funksiyası dayana bilər. Hesabın bağlanması bütün məlumatların dərhal silinməsi demək olmaya bilər; qanuni saxlama, mübahisə, təhlükəsizlik və audit üçün zəruri məlumat müvafiq müddətdə məhdud saxlanıla bilər.

16. Məxfilik Bildirişinə dəyişikliklər

Məlumat kateqoriyaları, məqsədlər, processor-lar, ölkələr, saxlama müddətləri və ya hüquqi əsaslar əhəmiyyətli şəkildə dəyişdikdə bildiriş yenilənməli və lazım gəldikdə yeni razılıq alınmalıdır. Yalnız “Son yenilənmə” tarixinin dəyişdirilməsi kifayət deyil; dəyişiklik tarixçəsi saxlanmalıdır.

17. Əlaqə və şikayət

Məxfilik sorğuları üçün hazırkı ümumi sayt əlaqəsi: info@naic.az. Telefon: +994 50 555 07 82. Dərcdən əvvəl ayrıca “privacy@...” ünvanı və məsul şəxs/rol təyin edilməsi tövsiyə olunur.

İstifadəçi həmçinin tətbiq olunan qanunvericilik çərçivəsində səlahiyyətli dövlət orqanına və ya məhkəməyə müraciət etmək hüququnu saxlayır.

Daxili data-flow və buraxılış checklisti

Production hosting, DB, object storage, backup, CDN, e-poçt/OTP, CRM/chatbot və gələcək payment provider-ların adı, ölkəsi və rolu inventarlaşdırılsın.

Fərdi məlumat informasiya sisteminin dövlət qeydiyyatı tələbi və mümkün istisna hüquqşünas tərəfindən ayrıca yoxlanılsın.

Hər forma üçün privacy notice linki və məqsəd-spesifik consent mətninin versiyası serverdə saxlanılsın.

Retention schedule backend job-ları ilə faktiki icra olunsun; “siyasətdə var, sistemdə yoxdur” uyğunsuzluğu buraxılmasın.

Refresh token-in localStorage istifadəsi production-da yenidən dizayn edilsin; XSS və token revocation modeli test edilsin.

Account deletion/data subject request üçün autentifikasiya, export, correction, delete/restrict/objection və audit axını yaradılıb test edilsin.

CV faylları malware scan, MIME/type yoxlaması, private object access və avtomatik expiry ilə qorunsun.

Kontakt lead-ləri üçün CRM daxilində giriş rolu və silinmə müddəti ayrıca tətbiq edilsin.

Analitika/reklam əlavə edilərsə əvvəlcədən data inventory, consent və policy update qapısı tətbiq edilsin.

Security incident response plan və hüquqi notification matrisi yazılı şəkildə təsdiqlənsin.

Frontend üzrə müəyyən edilmiş konkret məlumat axınları

register: firstName/lastName, email, optional phone, password -> /api/v1/auth/register;
verify/login: e-poçt + OTP -> auth verification endpoint-ləri;
profile: ad-soyad, telefon, locale -> /api/v1/users/me;
enrollment: userId, groupId, consentVersion, consentGivenAt -> /api/v1/enrollments;
application: applicationType, fullname, email, phone, letter + CV faylı -> /api/v1/applications;
contact: name, phone, email, note, interest, source -> /api/lead;
local/session storage: auth token-ləri, user cache, enrollment ID/attempt və offline subscribe e-poçtu.
