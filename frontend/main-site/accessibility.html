NEXORA ACADEMY

Əlçatanlıq

Rəqəmsal əlçatanlıq bəyanatı və təkmilləşdirmə planı

1. Öhdəlik

Nexora Academy rəqəmsal təhsil və müraciət xidmətlərinin əlilliyi olan şəxslər də daxil olmaqla mümkün qədər geniş istifadəçi qrupu üçün qavranılan, idarə olunan, anlaşılan və dayanıqlı olmasını hədəfləyir. Əlçatanlıq yalnız vizual dizayn məsələsi deyil; klaviatura, ekran oxuyucusu, böyütmə, səs/video alternativləri, hərəkət həssaslığı, dil, formalar və dinamik status mesajlarını əhatə edir.

2. Tətbiq olunan standart və uyğunluq hədəfi

Nexora-nın əsas texniki hədəfi W3C Web Content Accessibility Guidelines (WCAG) 2.2 Level AA-dır. WCAG 2.2 dörd prinsip üzərində qurulur: Perceivable (qavranılan), Operable (idarə olunan), Understandable (anlaşılan) və Robust (dayanıqlı).

Cari status: qismən uyğunluq / tam uyğunluq iddiası verilmir. Tam Level AA iddiası yalnız bütün tətbiq olunan A və AA meyarları üzrə reprezentativ səhifə/proses nümunələri test edildikdən, kritik qüsurlar aradan qaldırıldıqdan və nəticələr sənədləşdirildikdən sonra verilməlidir.

3. Bu bəyanatın əhatə dairəsi

ana səhifə və ümumi naviqasiya;
kurs, kateqoriya, kurs təfərrüatı və FAQ səhifələri;
təqaüd/karyera və əlaqə formaları;
register, login, OTP, password reset və account status axınları;
profil, tələbə kabineti və enrollments axını;
Şərtlər, Məxfilik və Əlçatanlıq səhifələri;
JavaScript ilə yaradılan dinamik komponentlər, status mesajları, slider və video elementləri.

4. Mövcud güclü tərəflər

Mənbə-kod üzrə ilkin audit aşağıdakı müsbət xüsusiyyətləri göstərir:

nəzərdən keçirilən statik şəkillərdə alt atributlarının geniş istifadəsi;
hesab, profil və enrollment formalarının çoxunda label-for və ya label wrapper vasitəsilə proqrammatik etiketləmə;
forma səhvlərində aria-invalid və status mesajlarında aria-live/role=status yanaşmaları;
mobil menyu və bəzi idarəetmələrdə aria-expanded və aria-label istifadəsi;
kurs pagination idarəetmələrində əvvəlki/növbəti düymələr üçün aria-label;
əsas hesab səhifələrinin əksəriyyətində html lang="az" istifadəsi;
mətn ölçüsünü sabit piksel görüntüsünə bağlamayan, responsiv struktura meyl edən CSS.

Bu müsbət məqamlar tam uyğunluq demək deyil; WCAG uyğunluğu bütöv səhifə və tam istifadəçi prosesi səviyyəsində qiymətləndirilir.

5.1. Klaviatura fokusunun görünməsi

Qlobal CSS button/input/select/textarea üçün outline: none tətbiq edir, lakin yalnız məhdud sayda komponent üçün ayrıca :focus-visible stili müəyyən edilib. Bu, klaviatura istifadəçiləri üçün bəzi idarəetmələrdə fokus yerinin görünməməsi riskini yaradır.

5.2. Skip link və əsas məzmuna sürətli keçid

Nəzərdən keçirilən HTML fayllarında “skip to main content” tipli bypass linki aşkar edilməyib. Uzun header/naviqasiya strukturunda bu xüsusiyyət klaviatura və ekran oxuyucusu istifadəçiləri üçün vacibdir.

5.3. Dil metadata-sı

faq.html və scholarships.html Azərbaycan dilində məzmun daşısa da html lang="en" kimi işarələnib. Bu, ekran oxuyucularında düzgün tələffüz və dil qaydalarının tətbiqinə mane ola bilər.

5.4. Əlaqə forması etiketləri

contact.html daxilində bəzi sahələr vizual

başlığı və placeholder istifadə edir, lakin proqrammatik

5.5. Hərəkət, autoplay və reduced motion

Layihədə smooth scrolling, çoxsaylı transition/animation və 4500 ms interval ilə autoplay slider davranışı mövcuddur. CSS/JS-də prefers-reduced-motion üçün ümumi alternativ aşkarlanmayıb. Hərəkətə həssas istifadəçilər üçün avtomatik hərəkəti azaltmaq/dayandırmaq lazımdır.

5.6. Video alternativləri

Nəzərdən keçirilən HTML-də 6 video elementi və 0 elementi aşkar edilib. Videolar nitq və ya vacib audio məlumat daşıyırsa, sinxron caption/subtitle və uyğun hallarda transcript/audio description təmin edilməlidir.

5.7. Dinamik/legacy komponentlərin accessible name bütövlüyü

Bəzi legacy/template hissələrində çoxsaylı ikon düymə və linklər JavaScript ilə sonradan aria-label alır. JavaScript uğursuz olduqda və ya komponent vəziyyəti dəyişdikdə accessible name-in qorunması ayrıca test edilməlidir.

5.8. JavaScript asılılığı

Sayt noscript mesajı göstərir və əsas funksiyaların əhəmiyyətli hissəsi JavaScript tələb edir. WCAG JavaScript-i qadağan etmir, lakin JavaScript aktiv olduqda bütün əsas funksiyalar keyboard/screen reader ilə işləməli, status dəyişiklikləri elan edilməli və səhvlər bərpa edilə bilən olmalıdır.

6. Alternativ çıxış və yardım

İstifadəçi əlçatanlıq maneəsinə görə kurs məlumatına, qeydiyyata, müraciətə və ya hesab funksiyasına çata bilmirsə, Nexora ağlabatan alternativ təqdim etməyə çalışmalıdır: məlumatın e-poçtla verilməsi, formanın əməkdaş tərəfindən qəbul edilməsi, mətn formatlı sənəd, caption/transcript və ya digər uyğun kanal.

7. Geribildirimdə hansı məlumat faydalıdır

problem yaşanan səhifənin adı və ya URL-i;
istifadə olunan cihaz və brauzer;
screen reader və ya digər assistive technology adı (istəyə bağlı);
nə etməyə çalışdığınız və nə baş verdiyi;
sizə uyğun alternativ format və ya həll forması.

İstifadəçidən diaqnostika üçün zəruri olmayan sağlamlıq və ya digər həssas məlumatları açıqlaması tələb edilməməlidir.

8. Texniki uyğunluq yanaşması

Nexora aşağıdakı minimum texniki praktikaları məhsul buraxılışının bir hissəsi kimi tətbiq etməlidir:

semantik HTML və düzgün heading strukturu;
bütün interaktiv elementlər üçün keyboard çıxışı və görünən focus;
accessible name/role/value və düzgün ARIA istifadəsi;
formalar üçün label, instruction, error identification və error summary/focus management;
şəkillər üçün məqsədə uyğun alt text; dekorativ şəkillər üçün boş alt;
rəngdən asılı olmayan vəziyyət göstəriciləri və WCAG AA kontrast;
200% və daha çox zoom/reflow testləri;
responsive touch target ölçüləri və pointer alternativləri;
caption/transcript və lazım olduqda audio description;
prefers-reduced-motion dəstəyi və autoplay üçün dayandırma nəzarəti;
düzgün lang və dil dəyişiklikləri metadata-sı;
status mesajları və dinamik yenilənmələrin assistive technology tərəfindən elan edilməsi;
accessible authentication: lazımsız cognitive testlərdən qaçmaq, password manager/paste dəstəyi və OTP axınını maneəsiz saxlamaq.

9. Test metodologiyası

Tam uyğunluq qiymətləndirməsi yalnız avtomatlaşdırılmış skanla aparılmamalıdır. Minimum test dəsti aşağıdakıları birləşdirməlidir:

Automated lint/a11y scan: HTML, accessible name, ARIA, contrast və form problemləri üçün.

Keyboard-only manual test: Tab/Shift+Tab, Enter/Space, focus order, modal/menu/slider davranışı.

Screen reader smoke test: əsas naviqasiya, register/login/OTP, form errors, enrollment və status mesajları.

Zoom/reflow və mobile test: 200–400%, dar viewport, landscape/portrait.

Reduced motion və high contrast/forced colors ssenariləri.

Video caption/transcript və media controls testi.

Real istifadəçi testləri: mümkün olduqda əlilliyi olan iştirakçılarla kritik proseslərin yoxlanması.

10. Əlçatanlıq dəyişikliklərinin idarə edilməsi

Yeni UI komponenti, kurs template-i, form, media və autentifikasiya axını production-a çıxmazdan əvvəl accessibility acceptance criteria olmalıdır. Kritik A/AA problemi buraxılışı bloklamalı; regresiya testləri CI/CD və manual QA-da saxlanmalıdır.

Accessibility bəyanatı yalnız saytın real vəziyyətinə uyğun yenilənməlidir. Məlum problem aradan qaldırıldıqda və ya yeni problem müəyyən edildikdə tarix və status dəyişdirilməlidir.

Mənbə-kod auditinin xülasəsi

20 əsas HTML səhifə nəzərdən keçirildi.
Statik HTML-də şəkillərin alt atributları geniş şəkildə mövcuddur.
faq.html və scholarships.html üçün səhifə dili “en” kimi qeyd edilib, baxmayaraq ki məzmun əsasən Azərbaycan dilindədir.
contact.html-də ən azı 4 input/textarea proqrammatik label olmadan müəyyən edildi.
Qlobal CSS button/input/select/textarea outline-ni söndürür; yalnız məhdud komponent üçün :focus-visible stili aşkar edildi.
Skip-to-main linki aşkar edilmədi.
6 video elementi üçün HTML səviyyəsində caption elementi aşkar edilmədi.
Autoplay slider və çoxsaylı animation/transition var; prefers-reduced-motion qaydası aşkar edilmədi.
Form error/status axınlarında aria-invalid və aria-live kimi yaxşı praktikalar mövcuddur.
